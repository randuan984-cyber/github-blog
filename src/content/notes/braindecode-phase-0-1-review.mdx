## 问题 1：对项目整体架构理解不清

### 问题
初次接触 braindecode 时，面对 `datasets`、`preprocessing`、`models`、`training` 等多个模块，不清楚各模块之间的关系，也不知道应该从哪里开始阅读。

### 调查
通过 README、源码目录、examples 和测试代码进行交叉查看，并重点分析运动想象和睡眠分期的官方示例。

### 失败原因
一开始直接从具体代码入手，容易陷入函数和参数细节，缺少对项目整体流程的认识。

### 根本原因
没有先建立“数据 → 预处理 → 模型 → 训练 → 预测”的整体认知框架。

### 解决方案
先根据 README 建立预期架构，再通过 examples 和源码逐层验证，明确各模块职责和典型入口。

### 经验教训
阅读陌生开源项目时，应先建立整体架构，再深入具体实现，避免陷入局部代码。

## 问题 2：错误判断官方示例包含完整伪影去除

### 问题
最初认为 EEG 输入模型前应该进行较完整的伪影去除，但实际阅读官方最小示例后发现并没有这一步。

### 调查
对比官方示例中的预处理流程，并进一步了解 MNE、EEG 预处理工具在信号清洗中的作用。

### 失败原因
将“实际 EEG 项目通常需要的完整预处理流程”和“官方最小示例用于快速验证模型的流程”混为一谈。

### 根本原因
没有首先明确示例代码的设计目标。

### 解决方案
重新区分“快速跑通 Demo”和“完整 EEG 数据处理”两个场景，确认 braindecode 示例重点是验证端到端训练流程，而不是完成所有信号清洗。

### 经验教训
分析代码时不能只根据经验推断功能，必须结合项目定位和实际实现进行验证。

## 问题 3：无法理解 EEG 输入形状 `(22, 1125)`

### 问题
看到模型输入形状 `(22, 1125)` 时，不清楚两个维度分别代表什么，以及 1125 为什么是这个数值。

### 调查
结合数据集参数、采样率和窗口长度进行反推。

### 失败原因
最初只把 shape 当作模型需要的参数，没有进一步追溯其对应的实际 EEG 数据含义。

### 根本原因
没有建立“数据采集参数 → 数据窗口 → 模型输入”的对应关系。

### 解决方案
确认 22 对应 EEG 通道数，采样率为 250 Hz，窗口长度为 4.5 s，因此：

`n_times = 4.5 × 250 = 1125`

最终明确输入形状来源于真实的数据采集和窗口切分参数。

### 经验教训
阅读深度学习代码时，不能只关注模型结构，还需要理解输入数据的物理意义和参数来源。输入 shape 的变化可能直接影响模型结构和实验结果。

## 阶段性总结

这阶段最大的收获不是记住了多少 braindecode API，而是建立了一套阅读陌生深度学习项目的方法：

**先建立整体假设 → 阅读源码和示例 → 验证假设 → 定位错误 → 找到根本原因 → 形成可复用的理解。**

后续进入阶段 2 后，将进一步通过实际运行官方示例，验证模型训练流程，并记录准确率、训练时间等实验结果，逐步从“理解项目”进入“实际使用和分析项目”。
